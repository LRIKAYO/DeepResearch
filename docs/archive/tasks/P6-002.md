## Accepted Activation Decisions

### ADR-P6-A — Document endpoint scope: Option A

The accepted P6-000 scope includes Document create/read/list plus Knowledge
search. A checkpoint draft narrowed P6-002 to create plus search without user
approval.

- **Option A — retain accepted scope:** implement create, read, list, and
  Knowledge search in P6-002.
- **Option B — narrow the first vertical slice:** implement create and search
  in P6-002, then schedule read/list in the next rolling batch.

Accepted: implement create, read, list, and Knowledge search in P6-002.

### ADR-P6-B — User isolation: Option A

The project requirement calls for permanent Knowledge search to consider
`user_id + project_id`. The current accepted MVP has no User/Auth/membership
model and its APIs explicitly promise Project scope only.

- **Option A — introduce ownership now:** expand P6-002 with a minimum
  User/Project ownership or membership Contract and trusted/authenticated user
  context, then enforce both identifiers on Document access and search.
- **Option B — keep the local single-user foundation:** retain Project-only
  isolation for P6-002, state that it is not multi-user safe, and require a
  separate architecture task before multi-user deployment.

Accepted: Project stores immutable `owner_user_id` from a trusted
`X-ResearchFlow-User-Id` dependency. Every Project and nested-resource lookup
uses current user plus Project. Document/Chunk do not duplicate user identity;
retrieval joins Project and filters both values. Existing rows require explicit
`RESEARCHFLOW_LEGACY_OWNER_USER_ID` backfill. Password/login/token issuance and
Product User CRUD remain out of scope.

  `src/researchflow/knowledge/`. Prefer heading hierarchy and paragraph
  boundaries. Pack normal blocks up to 2,000 Python characters and use
  2,000-character windows with 200-character overlap only for an overlong
  structural block; emitted non-empty chunks keep stable source order and
  consecutive zero-based indexes.

  the Document and all Chunks/vectors. Any failure leaves neither resource.

  filtering `documents.project_id` and `projects.owner_user_id` at that
  authoritative query boundary, ordering by

  the validated limit. Return `score = 1 - cosine_distance`.

- Use injected fake embeddings for deterministic tests and run one
  credential-safe, real configured embedding + pgvector smoke before DONE.
