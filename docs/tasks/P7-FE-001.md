## What the user should understand

1. The first `submit` argument is Graph input and may contain artifact context;
   the second argument's `context` is static LangGraph Run context.
2. Central wrapping prevents individual submit paths from forgetting scope or
   substituting another Project through options.
3. Project selection supplies transport context only; Backend authorization is
   repeated independently for every Knowledge request.
4. Switching Projects changes future Run context and does not rewrite existing
   thread checkpoints.

## Acceptance Criteria

- SDK run requests contain `context.knowledge_scope.user_id` and
  `context.knowledge_scope.project_id` in submit options, not Graph input.
- User ID comes from the existing local Frontend identity setting and Project
  ID comes from the currently selected Product Project.
- Lower-level submit callers cannot override the wrapper's scope.
- Artifact `context` remains an optional Graph input field and is never treated
  as access scope.
- Submission without a selected Project fails before an Agent run is created.
- Switching Projects changes the next run's context without changing prior
  checkpoints or treating thread metadata as authority.
- Existing Project/Session selection and stream behavior remain intact.
