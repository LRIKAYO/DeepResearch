Key Decisions:

- A permanent Document belongs to Project, never Research Session/thread/run.
- The first file boundary is one strict UTF-8 `text/markdown` multipart upload,
  bounded to 1,048,576 raw bytes.
- Document source text is stored internally in PostgreSQL but omitted from the
  first metadata responses.
- `201 Created` means Document plus every Chunk/embedding committed atomically
  and is searchable; any failure leaves no Document/Chunk row.
- Chunks are internal indexed records. `KnowledgeHit` is a typed runtime result,
  not Agent Evidence or a final Citation Schema.
- Project isolation is enforced in the authoritative retrieval query through
  Document membership.
- pgvector remains the preferred candidate rather than an approved physical
  implementation until P6-001 measures the real image/extension/model/dimension.
- Future Agent Knowledge scope remains an architecture decision; product IDs do
  not enter Agent State and thread metadata is not membership authority.

What the user should understand:

- Document is the durable Product source; Chunk is an internal retrieval unit;
  `KnowledgeHit` is provider output; Evidence is Agent working data.

- Project filtering belongs in the retrieval query, not the UI or LangGraph
  metadata.
- Physical vector schema cannot be chosen until embedding dimension and the
  real pgvector environment are measured.
