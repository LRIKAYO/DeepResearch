## What the user should understand

1. `KnowledgeScope` is trusted runtime input captured by the Tool closure;
   `query` and `limit` are the only model-controlled values.
2. `KnowledgeClient` transports scope to the existing authoritative Backend
   boundary; it does not authorize or query pgvector itself.
3. Backend hits become `user_upload` Evidence only after strict response
   validation and retain `document_id` plus `chunk_id`.
4. Validated Evidence becomes a JSON-safe payload before entering checkpointed
   Agent State because Pydantic model instances are not serializable by the
   installed LangGraph serializer.

## Acceptance Criteria

- The Tool schema exposes only `query` and optional `limit`; scope cannot be
  supplied or changed by the model.
- The HTTP request uses scope Project in the path and scope user in the trusted
  header, with query/limit only in JSON.
- Client timeout is 10 seconds; no retry occurs.
- Only HTTP `200` with a valid hit list succeeds. A valid empty list returns
  empty Evidence; status, timeout, transport, JSON, and response-schema failures
  raise the same sanitized Tool error.
- `user_upload` Evidence preserves UUID Document/Chunk provenance and filename.
- Existing Web results become valid `temporary_research` Evidence through the
  same Pydantic validator.
- Legacy `{source, content, relevance_note?}` Evidence is rejected rather than
  silently migrated.
- Current single-Web-Tool Agent behavior and all existing tests remain green.
- No P7-002 graph binding or Backend/Knowledge storage change appears.
